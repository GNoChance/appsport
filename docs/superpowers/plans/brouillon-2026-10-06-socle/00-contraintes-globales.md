## Global Constraints

Chaque ligne s'applique à toutes les tâches. Les valeurs sont copiées de la spec (`docs/superpowers/specs/2026-10-06-appsport-design.md` et ses sections 01 à 10). Une décision de ce plan qui tranche un point laissé ouvert par la spec est marquée **[décision plan]**.

- **Poste et outils** : Windows 11, Node ≥ 24.7 (`engines`, `.node-version` = `24`), pnpm 10 (`packageManager: pnpm@10.x`). Pas de Docker ni de Python en local. Tout test hors `infra` tourne sous Windows dans un seul processus Node.
- **Versions** (à figer dans le lockfile) : hono 4.13.x, @hono/node-server 2.1.x, kysely 0.29.x, zod 4.x, react 19.x, react-dom 19.x, vite 8.x, @vitejs/plugin-react, dexie 4.x, wouter 3.x, vitest (dernière majeure), fast-check 4.x, fake-indexeddb 6.x, @testing-library/react et happy-dom, @playwright/test 1.6x (Chromium et WebKit), typescript 7.0.x (CI non bloquante sous typescript 6.x), @biomejs/biome 2.x, esbuild, tsx, better-sqlite3 (dev seulement, pour rejouer les tests de l'adaptateur), bats (dev, tests des scripts hôte). Pas d'@anthropic-ai/sdk dans le socle.
- **Résolution TS [décision plan]** : `module: "preserve"`, `moduleResolution: "bundler"`, imports relatifs sans extension, `strict: true`, `noUncheckedIndexedAccess: true`, `verbatimModuleSyntax: true`, `noEmit: true`. Les paquets internes exportent `./src/index.ts`. Le serveur tourne en dev et en E2E avec `tsx` et en production comme bundle esbuild unique `server.mjs`.
- **Paquets** : `@appsport/contracts` (Zod, constantes, registre, sans logique), `@appsport/domain` (TS pur, sans horloge ni E/S : la date et l'aléa sont passés en paramètres), `@appsport/server`, `@appsport/web`. Dépendances autorisées : domain → contracts ; server → contracts, domain ; web → contracts, domain ; web (dev) → server pour `@appsport/server/testing`.
- **Commandes** : `pnpm lint` (biome check), `pnpm typecheck` (tsc --noEmit dans chaque paquet), `pnpm test` (vitest run, tous projets), `pnpm --filter @appsport/<pkg> test -- <motif>`, `pnpm --filter @appsport/web test:e2e -- <spec>`, `pnpm test:infra` (bats sur `infra/host/test`).
- **Langues** : identifiants, tables, colonnes, codes d'erreur et commits techniques en anglais ; textes d'interface, messages CLI destinés à l'admin et documentation en français ; messages de commit au format conventionnel en français (`feat(auth): invitations à usage unique`). Scopes : `socle`, `db`, `auth`, `admin`, `profil`, `salles`, `privacy`, `synchro`, `web`, `pwa`, `infra`, `ops`, `docs`, `ci`.
- **Unités** : charges et poids en grammes entiers (`*G`, `*_g`). Dates civiles `YYYY-MM-DD`, horodatages ISO 8601 UTC (`toISOString()`), dates civiles et âge à l'heure de `Europe/Paris`.
- **SQLite** : `node:sqlite`, `journal_mode=WAL`, `synchronous=FULL`, `foreign_keys=ON`, `busy_timeout=5000`, tables `STRICT`. Il n'y a pas de type DATE ni BOOLEAN : booléen `INTEGER CHECK (x IN (0,1))`, JSON `TEXT CHECK (json_valid(x))`, énumérations `TEXT CHECK (x IN (...))`. Kysely avec `CamelCasePlugin` : clés de `Database` et colonnes en camelCase côté TS, snake_case en base.
- **Identifiants** : UUIDv7 en TEXT (client pour les tables J, serveur sinon). Exceptions : `id = owner_id` pour `training_profile` et `health_screening` ; `gym_equipment.id = gym_id || ':' || equipment_code` ; `home_equipment.id = place_id || ':' || equipment_code`. Le serveur valide le format UUIDv7 sans jamais ordonner selon son horodatage.
- **Colonnes +SYNC** : `owner_id`, `rev` (valeur de `server_meta.sync_counter`, incrémenté à chaque écriture de ligne), `created_at`, `updated_at` (heure serveur), `updated_by`, `deleted_at`. Index `(rev)` et `(owner_id, rev)`. `owner_id` vient toujours de la session, jamais du corps.
- **Ajouts au modèle [décision plan]** : (1) `server_meta.tombstone_purge_rev INTEGER NOT NULL DEFAULT 0`, nécessaire au `410 watermark_expired` de R-SYN-23 ; (2) colonnes de contenu de `health_screening` et `limitation` nullables, avec `CHECK (deleted_at IS NOT NULL OR <contenu NOT NULL>)`, pour permettre la tombstone sans contenu (R-SYN-9, P-CST-3) ; (3) `training_profile.goal/experience/days_per_week/session_minutes` nullables tant que l'onboarding n'est pas terminé ; (4) `user.onboarding_step` ∈ `goal|sport|place_kind|place|experience|availability|health|ready` ou NULL (dernier écran validé).
- **Registre** : `entityRules` (`packages/contracts/src/entity-rules.ts`) couvre les 18 tables du socle et chacune de leurs colonnes. Un test CI échoue si une table ou une colonne de `sqlite_schema` est absente du registre, ou si une table C1 à C3 liée à un utilisateur n'est pas `exported` avec `onUserDelete` ∈ {`cascade`, `anonymize`}.
- **Catégories** : C0 interne, C1 personnel, C2 santé (consentement `health` exigé), C3 sensible (brique 4). Les colonnes `*_hash` sont listées dans `secretColumns` : jamais exportées, synchronisées, journalisées ni renvoyées par l'API.
- **Format d'erreur API [décision plan]** : tout corps d'erreur est `{ "error": <ApiErrorCode>, ...extra }`. Exemples : `410 {"error":"account_deleted"}` (P-DRT-4), `410 {"error":"watermark_expired"}`, `426 {"error":"protocol_unsupported","serverProtocol":1,"minProtocol":1}`, `403 {"error":"health_consent_required"}`. Le client agit sur `error`, jamais sur le seul statut.
- **Admin et données des autres** : toute lecture C1 à C3 est filtrée par l'utilisateur de session. Une session admin qui demande une ressource C1, C2 ou C3 d'un autre reçoit `404`, jamais `403` (P-ADM-2). Aucune route `/api/admin/*` ne renvoie de champ C1 à C3.
- **En-têtes HTTP** (toutes réponses) : `Strict-Transport-Security: max-age=31536000` ; `Content-Security-Policy: default-src 'self'; img-src 'self' data:; object-src 'none'; base-uri 'none'; frame-ancestors 'none'; form-action 'self'` ; `Referrer-Policy: no-referrer` ; `X-Content-Type-Options: nosniff` ; `Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=(), usb=()` ; `X-Appsport-Epoch: <server_epoch>` sur chaque réponse `/api/*`. Aucun script en ligne dans `index.html`. Aucune ressource tierce (P-LOG-4).
- **CSRF** : POST, PUT, PATCH et DELETE exigent `Origin` égal à `APP_ORIGIN` (sinon `403 origin_mismatch`). POST, PUT et PATCH exigent aussi `Content-Type: application/json` (sinon `415 unsupported_media_type`). Le client envoie `{}` quand il n'y a rien à transmettre. Les en-têtes `Tailscale-User-*` sont ignorés.
- **Cookie de session** : `__Host-session=<jeton base64url 32 octets>; HttpOnly; Secure; SameSite=Lax; Path=/`, sans `Domain`, quand `APP_ORIGIN` commence par `https://`. **[décision plan]** Sur une origine `http://localhost:*` (dev et E2E), le cookie s'appelle `dev-session` et n'a pas `Secure`. Seule l'empreinte SHA-256 est stockée. Inactivité 90 j, durée absolue 365 j.
- **Comptes** : `MIN_AGE` = 16 ; invitation 7 j (`INVITATION_TTL_DAYS`), invitation d'amorçage 24 h, réinitialisation 24 h ; code de 16 caractères Crockford base32 (80 bits), affiché `XXXX-XXXX-XXXX-XXXX`, empreinte SHA-256 ; saisie insensible à la casse, aux espaces et aux tirets, avec I/L → 1 et O → 0 ; note ≤ 60 caractères ; pseudo de 3 à 24 caractères (lettres avec accents, chiffres, `.`, `_`, `-`), clé NFKC puis minuscules, réservés `admin`, `appsport`, `systeme` ; mot de passe de 12 à 128 points de code après NFC, 14 au moins pour un admin ; Argon2id m = 19456 Kio, t = 2, p = 1, sel 16 octets, format PHC.
- **Limitation des tentatives** (en mémoire) : par pseudo normalisé, attente de 1 min à partir du 5e échec consécutif, doublée à chaque échec, 15 min au plus ; au 10e échec sur une heure glissante, refus pendant 1 h. Par IP du tailnet : 30 échecs par heure. Vérification des codes d'invitation et de réinitialisation : 20 essais par heure et par IP.
- **Synchro** : `SYNC_PROTOCOL` = 1, `MIN_PROTOCOL` = 1, en-tête `X-Appsport-Protocol` ; `SYNC_PUSH_MAX` = 200 ; `limit` du pull = 500 ; `TOMBSTONE_TTL` = 90 j ; `applied_op` purgée à 12 mois ; `EPOCH_RESEND_DAYS` = 60 ; `SYNC_TIMEOUT_MS` = 4000 ; reprises de 2 s à 5 min ; synchro 2 s après une série validée, toutes les 60 s quand l'outbox n'est pas vide et l'appli visible, vidage limité à 4 s avant le coach ; watermark opaque `<server_epoch>:<rev>`. L'état connecté ne vient jamais de `navigator.onLine`.
- **Classes de synchro** : J (outbox ; dans le socle, seulement `sync_rejection`, dont le client n'écrit que `dismissed_at`), D (rien dans le socle), E (API en ligne ; hors ligne, refus avec le message « Nécessite le réseau »), C (catalogue par ETag), H (jamais dans Dexie).
- **Prêt hors ligne** : vert si et seulement si la coquille du build courant est en précache, le catalogue local correspond à la dernière `catalog_version` connue, les illustrations référencées sont en cache et un pull a réussi il y a moins de 24 h.
- **PWA** : caches `shell-<buildHash>` et `illustrations-v1` ; `index.html` et `sw.js` en `Cache-Control: no-cache` ; fichiers hachés en `public, max-age=31536000, immutable` ; mode prompt ; recherche de mise à jour au lancement, au retour au premier plan et toutes les 60 min ; jamais de bandeau pendant une séance (`activeSessionId`) ni pendant l'onboarding ; IndexedDB n'est jamais effacé par une mise à jour ni par l'interrupteur d'urgence (`SW_KILL_SWITCH=1`).
- **Configuration serveur** : uniquement par variables d'environnement. `APP_ORIGIN` (obligatoire), `APP_VERSION` (défaut `dev`), `PORT` (3000), `HOST` (`0.0.0.0`), `APPSPORT_DATA_DIR` (`/data`), `APPSPORT_PUBLIC_DIR`, `APPSPORT_CONTENT_DIR`, `SW_KILL_SWITCH` (`1` = actif), `COACH_MODEL` (`claude-opus-5-5`), `ANTHROPIC_API_KEY` (lu, inutilisé dans le socle).
- **Image** : `ghcr.io/gnochance/appsport:vX.Y.Z`, base `node:24-slim`, contenu `server.mjs`, `public/` et `data/`, sans `node_modules` ; port 3000 ; utilisateur 1000 ; `read_only` avec `tmpfs /tmp` ; arrêt propre sur SIGTERM en moins de 10 s ; `mem_limit: 512m` ; port publié `127.0.0.1:3000:3000` uniquement ; journaux JSON sur stdout sans corps, cookie, jeton, code, chaîne de requête, valeur C1 à C3 ni secret.
- **Garde de démarrage** : refus de démarrer sans `/data/.appsport-volume` ou sans `/data/appsport.db`, sauf pour `init`. L'appli ne crée jamais de base vide. Les migrations s'appliquent au démarrage, dans une transaction. Une migration inconnue marquée `breaking` interdit le démarrage ; des migrations inconnues toutes non cassantes le permettent.
- **Exploitation** : instantanés quotidiens à 03:30 et avant chaque déploiement, 3 de chaque type gardés dans `/data/snapshots/` (`daily-AAAAMMJJ.db`, `pre-vX.Y.Z.db`) ; restic `local` (`/srv/backup/restic`) et `offsite` (B2, bucket `appsport-backups`), `forget --keep-daily 30 --prune` ; tags restic `daily` et `pre-deploy` ; timers : `appsport-alive` toutes les 5 min, `appsport-backup` à 03:30, `appsport-check` à 04:00, `appsport-restore-test` le 1er dimanche du mois à 05:00 ; attente de `/api/health` de 2 min au plus ; séances `in_progress` de moins de 3 h affichées avant un déploiement.
- **Tests** : TDD (test rouge avant le code), dépendances injectées (`Clock`, `IdGen`, `Db`), SQLite en mémoire, fake-indexeddb, aucun réseau externe. Interdit : `navigator.onLine` comme source de vérité, `Date.now()` ou `Math.random()` dans `packages/domain`, accès direct à Dexie depuis un composant d'écran (passer par `repos/`).
- **Hors périmètre du socle** : tables et écrans des briques 2 à 5, `data:export`, coach et `AiClient`, `data:validate`, `svg:check`, écran d'édition des réglages de charge (brique 3). Le socle livre les points d'extension : registre, taxonomie, `recommendTemplate` testé sur des modèles factices, catalogue vide servi par ETag, `SYNC_HOOKS` vide.
